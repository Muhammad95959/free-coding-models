## `command not found: free-coding-models`

**Cause:** npm's global bin directory is missing from your shell `$PATH`.

**Fix:** Add the npm global prefix to `$PATH` in `~/.zshrc` or `~/.bashrc`:

```bash
export PATH="$PATH:$(npm config get prefix)/bin"
source ~/.zshrc
```

## HTTP 429 (Rate Limit Exceeded)

**Cause:** A provider's rate-limit window is exhausted. Rate-limited providers like **OpenRouter** (50 req/day free) are the most sensitive — one overloaded model re-pinged every cycle can burn your quota in minutes.

**Fix:**
1. FCM **auto-pauses** a provider the moment its probe gets a `429` (it honors the `Retry-After` header) and shows a footer chip like `⏸ openrouter 14h`. Wait it out, or add another provider's key.
2. Run the router (`free-coding-models --daemon-bg`) so requests fail over to an alternative provider in the active set.
3. Add keys for additional providers (Google AI, Cerebras, DashScope, NVIDIA) in Settings (**`P`** in the TUI).

> Leave a provider's key empty if you don't need authenticated probes — anonymous probes still work for liveness checks and won't burn your personal quota.

## HTTP 401 / 403 (Auth Error)

**Cause:** Invalid or expired API key.

**Fix:**
1. Check the key in TUI Settings (**`P`**) or the Web Dashboard **Settings** page (use the **Test key** button).
2. Force-rebuild the probe cache so the bad state clears:

```bash
free-coding-models --reprobe
```

Keys are stored in `~/.free-coding-models.json`. The TUI reads env vars first; export a fresh key (`export GROQ_API_KEY=…`) if the config value is stale.

## `Port 19280 in use`

**Cause:** Another daemon process is already running (or the port is occupied).

**Fix:**

```bash
free-coding-models --daemon-stop     # stop the running daemon
lsof -i :19280                        # check what's listening
```

Note the daemon scans `19280`–`19289` if the preferred port is busy. The catalog-only `web` dashboard uses a different port (`3333`, `FCM_WEB_PORT`).

## Broken models keep showing up

FCM auto-hides models that the probe cache marked broken (e.g. persistent 401s or offline endpoints) across sessions. To inspect them:

```bash
free-coding-models --show-broken       # CLI — don't auto-hide this run
# …or press Shift+B in the TUI (footer: ⚡ N cached · 🔴 M broken)
```

To start completely fresh, nuke the cache:

```bash
free-coding-models --reprobe           # rebuild the 24h probe cache
```

## OpenCode / Pi model list not updating

Re-run the tool launcher to re-inject the current model into the tool's config:

```bash
free-coding-models --opencode          # OpenCode
free-coding-models --pi                # Pi
```

For the agent extensions, use `/fcm rescan` (OpenCode) or `/fcm` (Pi) to force a fresh scan.

## How accurate are the latency numbers?

Real round-trip times measured by your machine. Results depend on your network and provider load at that moment. The **Stability Score** (0–100) is a better guide than a single ping — it folds in p95 latency, jitter, spike rate, and uptime.
