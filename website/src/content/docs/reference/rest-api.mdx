The `free-coding-models` daemon serves an **OpenAI-compatible router** plus a **Web Dashboard API** on the same port (`19280` in `--daemon` mode). Point any OpenAI-compatible client at `http://localhost:19280/v1` with model `fcm`.

## Base URL

```
http://localhost:19280
```

---

## Router endpoints (`/v1/...`)

| Method | Endpoint | Purpose |
|--------|----------|---------|
| `POST` | `/v1/chat/completions` | Route through the active set, with automatic failover |
| `POST` | `/v1/sets/:name/chat/completions` | Route through a named set |
| `GET` | `/v1/models` | Virtual models (`fcm`, `fcm:set-name`) |
| `GET` | `/health` | Daemon status JSON |
| `GET` | `/stats` | Routing, health, request log, token + probe-cache + quota + runtime stats |
| `GET` | `/stream/events` | Live SSE events for router updates |
| `POST` | `/daemon/probe-mode` | Set probe mode (`eco` / `balanced` / `aggressive`) via JSON body |

---

## Web Dashboard endpoints (same port in `--daemon` mode)

| Method | Endpoint | Purpose |
|--------|----------|---------|
| `GET` | `/` | Web dashboard HTML |
| `GET` | `/api/models` | All model data with latency stats |
| `GET` | `/api/config` | Provider config (keys masked) |
| `GET` | `/api/events` | Live SSE events for the dashboard |
| `GET` | `/api/key/:provider` | Reveal the full API key for a provider |
| `POST` | `/api/settings` | Save API keys and provider toggles |

## Examples

### Chat completion (`POST /v1/chat/completions`)

```bash
curl http://localhost:19280/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "fcm",
    "messages": [
      {"role": "user", "content": "Write a Python string reverse function."}
    ]
  }'
```

The `model` field accepts `fcm` (route through the active set) or `fcm:set-name` to target a specific set. Authentication uses key `fcm-local`.

### Health (`GET /health`)

```bash
curl http://localhost:19280/health
```

### Stats (`GET /stats`)

Returns routing stats, per-model health, the request log, token counters, the probe cache, quota snapshots, and runtime telemetry:

```bash
curl http://localhost:19280/stats | jq '.quota, .runtime'
```

### Probe mode (`POST /daemon/probe-mode`)

```bash
curl -X POST http://localhost:19280/daemon/probe-mode \
  -H "Content-Type: application/json" \
  -d '{ "probeMode": "aggressive" }'
```

## Virtual model IDs

| Model ID | What it routes to |
|----------|-------------------|
| `fcm` | The **active set** (`fast-coding` by default) |
| `fcm:set-name` | A named set, e.g. `fcm:my-coding-set` |
| `groq/<id>`, `cerebras/<id>`, … | Pin a specific provider/model for A/B testing |
