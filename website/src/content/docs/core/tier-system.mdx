Every model in the catalog is tiered by its **SWE-bench Verified** score — the industry-standard benchmark for real coding tasks. This lets you filter to models that are actually capable of the work you're doing, not just fast.

## Tier scale

| Tier | SWE-bench | Best for |
|------|-----------|----------|
| <Badge variant="s-plus">S+</Badge> | **≥ 70%** | Complex refactors, real-world GitHub issues |
| <Badge variant="s">S</Badge> | **60–70%** | Most coding tasks, strong general use |
| <Badge variant="a-plus">A+</Badge> / <Badge variant="a">A</Badge> | **40–60%** | Solid alternatives, targeted programming |
| <Badge variant="b">A-</Badge> / <Badge variant="b">B+</Badge> | **30–40%** | Smaller tasks, constrained infra |
| <Badge variant="b">B</Badge> / <Badge variant="c">C</Badge> | **Under 30%** | Code completion, edge/minimal setups |

> SWE-bench scores come from the model's official report or community evaluation (swe-bench.com / swe-rebench.com). Some models have no published score yet (shown as `-`) but are still tiered by provider/model signals.

## Filter and sort by tier

### In the TUI

Press **`T`** to cycle the tier filter (All → S+ → S → A+ → A → A- → B+ → B → C → All). Press **`S`** to sort by SWE-bench score.

### From the CLI

`--tier` filters by **tier family** — a single letter expands to a range:

| Flag | Tiers shown |
|------|-------------|
| `--tier S` | S+ and S |
| `--tier A` | A+, A, A- |
| `--tier B` | B+ and B |
| `--tier C` | C only |

```bash
# S-tier family only (S+ and S)
free-coding-models --tier S

# Elite-focused preset (S-tier filter + verdict sort, resettable in-app)
free-coding-models --premium

# Top tiers only (A+, S, S+)
free-coding-models --best

# Sort by SWE score, descending
free-coding-models --sort swe --desc
```

## Extended benchmark catalog

FCM layers an extended benchmark catalog (`src/data/benchmarks.json`) on top of `sources.js` — adding Coding, Math, Agentic, Reasoning, MMLU-Pro, GPQA, and HLE scores for models that have them (the footer shows `📊 bench N`).

## Drift detection (`--check-drift`)

The catalog is enriched with live `models.dev` community data in the background (footer: `📡 N live · M curated`). To diff your local `sources.js` against upstream `models.dev`:

```bash
free-coding-models --check-drift
```

This prints a drift report and exits `1` on mismatch — handy for CI to catch when a provider changes its model list. Use `--drift-threshold <N>` to only fail when N+ mismatches are found.
