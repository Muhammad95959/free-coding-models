FCM continuously health-probes every model so you see live latency, status, and verdict. The same probe data powers the TUI, the Web Dashboard, the router's circuit breaker, and the persistent 24h cache shared across all surfaces.

## Adaptive ping cadence

The ping loop sends 1-token chat-completion probes to measure end-to-end API latency **and status code**, not just DNS reachability — so a wrong API key is caught immediately. The cadence adapts to how busy the catalog is:

- **2s burst** for the first 60s after launch
- **10s normal** once most models have responded
- **30s idle** slowdown after inactivity

Override the interval if you need to:

```bash
free-coding-models --ping-interval 5000   # ping every 5s
```

## Live verdicts

Model health is summarized as a human-readable verdict. The **Stability** column is the composite 0–100 score; the verdict is a quick label.

| Verdict | Meaning |
|---------|---------|
| 🟩 **Perfect** | Avg under 400ms with stable p95/jitter |
| 🟢 **Normal** | Avg under 1000ms, consistent responses |
| 🟡 **Spiky** | Good avg but erratic tail latency (p95 >> avg) |
| 🟠 **Slow** | Avg 1000–2999ms |
| 🔴 **Very Slow** | Avg 3000–4999ms |
| 🔥 **Overloaded** | Server returned 429/503 (rate limited or capacity hit) |
| 🟥 **Unstable** | Was previously up but now timing out, or avg > 5000ms |
| ⚫ **Not Active** | No successful pings yet and the model is currently down |
| ⏳ **Pending** | First usable latency sample is still missing |

The top-3 models by the current sort get 🥇🥈🥉 medal borders. Press **`B`** to sort by Stability, or **`V`** to sort by verdict.

→ **Stability formula & full column reference:** [`docs/stability.md`](https://github.com/vava-nessa/free-coding-models/blob/main/docs/stability.md)

## Persistent probe cache

Every health-probe result is cached to `~/.free-coding-models/probe-cache.json` for **24 hours** and **shared across all surfaces** (CLI TUI, Web Dashboard / daemon, Tauri Desktop).

- **Warm start** renders the full ranking in under 500ms using cached results, then re-pings only models that are due (broken or past TTL).
- **Broken models** are auto-hidden across sessions — a model that 401s today stays out of tomorrow's default view, and recovers automatically when it returns `ok`.
- **Cross-process safe** — debounced flush + atomic rename + read-merge-write, so the CLI and the daemon share the file without clobbering each other.

| Flag / key | Effect |
|------------|--------|
| `--reprobe` / `--no-cache` | Nuke the cache; ping everything fresh |
| `--probe-ttl <ms>` | Override the 24h TTL (e.g. `--probe-ttl 3600000` for 1h) |
| `--show-broken` | Don't auto-hide broken models this run |
| `Shift+B` (TUI) | Toggle broken-model visibility (footer: `⚡ N cached · 🔴 M broken`) |

## Circuit breaker (router)

The Smart Model Router's circuit breaker tracks each model in your active set. This is the same probe data, expressed as routing state:

| State | Meaning |
|-------|---------|
| 🟢 **Healthy** | Last probe returned 2xx — route here freely |
| 🔴 **Down** | Last 3 probes failed — skip until cooldown |
| 🟡 **Recovering** | Cooldown expired — retrying with 1 request |
| 🟠 **Auth error** | 401/403 — your API key is wrong for this model |
| ⚪ **Deprecated** | Removed from the catalog — will be replaced |

### Auto-failover

When a request to `http://localhost:19280/v1` (model `fcm`) hits a transient failure (`429`, `5xx`, timeout), the router fails over to the next healthy model in the active set. If *all* models fail, it returns a `503` with a `models_tried` list in the body for debugging. Auth problems are tracked separately so bad credentials never poison the circuit breaker.

→ **Routing behavior & auto-heal:** [Smart Model Router](/docs/core/router-daemon)
