# Runtime telemetry: real-world success rate, tok/s, recent calls

> **Priority**: P1 — this is our **differentiating angle**: "82% on the benchmark, *but* 38% real-world success rate at 4 tok/s this week". No competitor exposes this honestly.
> **Inspiration**: `apmantza/pi-free` — `lib/telemetry.ts`.
> **Cross-surface**: collected by the daemon (the only surface that proxies real traffic); consumed by CLI TUI, Web, and Tauri.

---

## 1. Why

Our SWE-bench / tier scores are **static and self-reported** by model providers — a model can advertise 82% and still fail half its real requests through a flaky gateway, or stream at 2 tok/s because the free tier is throttled. pi-free hooks Pi's `turn_end` event and persists, per model:

- `totalCalls`, `successCalls`, `errorCalls` → **real success rate**
- `totalLatencyMs`, `avgLatencyMs`, `avgTokensPerSecond` → **real throughput**
- `recentCalls[]` (last 50) → debugging

We already have `src/core/telemetry.js` (used for product analytics — daemon start/stop, failover, etc.) **but it does not track per-model runtime performance**. This task adds a **second** telemetry stream — *runtime model telemetry* — that becomes a first-class ranking signal and a public "honesty" differentiator.

**Strategic framing**: this turns FCM from "shows you marketing benchmarks" into "shows you what *actually* works on free tiers right now". That's a story no other tool tells.

---

## 2. Goals / Non-goals

### Goals
- [ ] Capture per-model runtime metrics on every routed request through the daemon.
- [ ] Persist to a dedicated JSON file (separate from product telemetry, which is sent upstream).
- [ ] Expose a **real-world score** alongside SWE-bench in the TUI (new sort key, new column).
- [ ] Provide a "Model runtime report" TUI screen (per-model breakdown + recent calls).
- [ ] Privacy: **local-only by default**, opt-in to share (future aggregate leaderboard).

### Non-goals
- Streaming token extraction for partial responses (the PRD already lists this as a known gap; out of scope here).
- Sharing/leaderboard (future task once we have data).
- Collecting prompt/response content (we store metadata only: success, latency, tokens, error).

## 3. Technical design

### 3.1 File location

```
~/.free-coding-models/runtime-telemetry.json
```

Separate from product telemetry. Atomic write (reuse the helper from t1). Bounded size (see 3.5).

### 3.2 Schema (mirror pi-free, adapt to our model shape)

```jsonc
{
  "version": 1,
  "models": {
    "nvidiaNim/z-ai/glm-5.2": {
      "totalCalls": 142,
      "successCalls": 131,
      "errorCalls": 11,
      "totalTokens": 184320,
      "totalPromptTokens": 162000,
      "totalCompletionTokens": 22320,
      "totalLatencyMs": 874300,
      "totalCost": 0,                 // free tier
      "recentCalls": [
        {
          "timestamp": 1753478400000,
          "provider": "nvidiaNim",
          "model": "z-ai/glm-5.2",
          "success": true,
          "latencyMs": 1840,
          "promptTokens": 1200,
          "completionTokens": 340,
          "totalTokens": 1540,
          "tokensPerSecond": 184.7,
          "stopReason": "stop",
          "error": null
        }
        // ... capped at 50
      ],
      "lastUpdated": 1753478400000
    }
  },
  "lastUpdated": 1753478400000
}
```

**Derived on read** (don't persist, recompute):
```js
avgLatencyMs       = totalLatencyMs / totalCalls;
avgTokensPerSecond = totalCompletionTokens / (totalLatencyMs / 1000);
successRate        = successCalls / totalCalls;
```

### 3.4 Hook point: daemon reverse proxy

The daemon already tracks token usage for the `/stats/tokens` endpoint (per PRD: "Non-streaming OpenAI `usage` fields are tracked daily/all-time"). Extend that same response handler to also call `recordModelCall`:

```js
// in router-daemon.js, after the upstream response completes:
recordModelCall(providerKey, routedModelId, {
  success: !errored,
  latencyMs: Date.now() - requestStart,
  promptTokens: usage?.prompt_tokens ?? 0,
  completionTokens: usage?.completion_tokens ?? 0,
  stopReason: finishReason,
  error: errorMessage,
});
```

**For streaming**: capture `usage` from the final SSE chunk (OpenAI sends it when `stream_options.include_usage`). For upstreams that don't, fall back to counting streamed chunks (rough estimate). This is the known gap; do the easy case first.

### 3.5 Bounded size

- `recentCalls` capped at **50** per model (FIFO).
- On flush, prune models with `lastUpdated` older than **30 days** (configurable).
- Worst-case size: ~238 models × 50 calls × ~200 bytes = ~2.4 MB. Acceptable. Add a `--clear-runtime` flag to wipe.

### 3.6 Real-world score (the ranking signal)

Composite score so the TUI can sort by it (new sort key, candidate `W` for "world"/real-world, currently free):

```js
function getRealWorldScore(providerKey, modelId) {
  const t = getModelTelemetry(providerKey, modelId);
  if (!t || t.totalCalls < MIN_CALLS_FOR_SCORE) return null; // not enough data yet

  const successRate = t.successCalls / t.totalCalls;          // 0..1
  const speed       = normalizeSpeed(t.avgTokensPerSecond);    // 0..1 (sigmoid)
  const recency     = recencyDecay(t.lastUpdated);             // 0..1 (1=today, 0=30d ago)

  // Weights — TUNE WITH VANESSA before shipping
  return Math.round((successRate * 0.6 + speed * 0.25 + recency * 0.15) * 100);
}
```

- `MIN_CALLS_FOR_SCORE = 5` — don't show a score until we have signal.
- When `null`, the TUI falls back to SWE-bench (don't punish new models).

### 3.7 TUI surface

- **New column** `Real` (or `RW` for "real-world"): shows the score or `–` when insufficient data.
- **New sort key** `W`: sorts by real-world score descending.
- **New screen** (`Shift+W`? coordinate with t1's `B` and existing `Shift+R/S/T`): "Runtime Report" — pick a model, see success rate, avg latency, avg tok/s, error breakdown (top errors), recent calls list.
- Footer chip when data exists: `📈 1,420 calls tracked`.

### 3.8 Honesty framing

In README + dashboard, frame this as:
> "SWE-bench is what the vendor claims. Real-world score is what *we measured* routing through FCM. The gap is the truth."

This is genuinely novel — no other free-model picker exposes this.

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Cold-start bias (few calls → noisy score) | `MIN_CALLS_FOR_SCORE=5` + recency decay; show `–` until enough data. |
| A bad model gets a high score from 5 lucky calls | Bayesian shrinkage toward 0.5 for low N (optional refinement; document as future). |
| Privacy concern | Local-only by default, explicit opt-in for any future sharing; never store content. |
| File grows | 50-call cap + 30-day prune on every flush. |
| Streaming token gap | Document as known limitation; capture when `include_usage` is present, estimate otherwise. |
