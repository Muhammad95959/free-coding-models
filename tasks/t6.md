# Provider thinking-compat layer (DeepSeek/Kimi/MiMo reasoning format)

> **Priority**: P3 — **conditional** on whether we stream real model responses (playground / router). If we only ever *ping*, defer this. If the router proxies real reasoning traffic, this is essential.
> **Inspiration**: `apmantza/pi-free` — `lib/provider-compat.ts` + `providers/qoder/thinking-parser.ts`.
> **Cross-surface**: applies to the daemon reverse proxy and the playground; CLI ping doesn't need it.

---

## 1. Why

Reasoning models (DeepSeek R1/V4, Kimi K2, MiMo, Qwen3.7 thinking) emit their chain-of-thought via a `reasoning_content` field or `<thinking>...</thinking>` HTML-style tags. When routed through a gateway/proxy (OpenRouter, Cline, OpenCode), the **upstream format varies** and the reasoning is silently dropped or corrupted unless we normalize it. Concretely:

- **DeepSeek-style** gateways need `reasoning_content` replayed on assistant messages + `thinkingFormat: "deepseek"`.
- **Kimi K2.6 via OpenRouter** (their issue #5309) needs `reasoning_content` replayed but **without** the DeepSeek thinkingFormat override.
- **MiMo / Xiaomi** reasoning models expose OpenAI-compatible reasoning controls but aren't DeepSeek-format.
- **Qoder / some DeepSeek gateways** emit `<thinking>` tags inline in the text stream rather than a structured field.

pi-free detects the family from a "haystack" (id+name+family+provider lowercased) and applies the right `compat` object. They also ship a streaming `ThinkingTagParser` that extracts inline tags safely without emitting partial tags across chunk boundaries.

For us, this matters **only where we proxy or display real model output** — i.e. the router daemon and any playground. Our ping only checks latency/availability, so it doesn't need this.

---

## 2. Goals / Non-goals

### Goals
- [ ] Detect model family from id+name+label (DeepSeek, Kimi, MiMo, Qwen3.x thinking, generic `<think>` tag emitters).
- [ ] Produce a `compat` object per model that the daemon applies when proxying.
- [ ] Stream parser that extracts `<thinking>/<think>/<reasoning>/<thought>` tags into structured thinking events.
- [ ] Preserve reasoning across retries/failover (replay `reasoning_content` on assistant messages).

### Non-goals
- Applying compat to ping requests (they don't carry reasoning we care about).
- Supporting every gateway's quirks day-one — start with DeepSeek, Kimi, MiMo, generic tags.
- Auto-tuning `reasoning_effort` per model (future; the compat layer just *enables* it).

## 3. Technical design

### 3.1 Family detection: `src/core/thinking-compat.js`

Adapt pi-free's haystack approach:

```js
export function getModelHaystack(model) {
  return [model.id, model.label, model.family, model.providerKey]
    .filter(Boolean).join(' ').toLowerCase();
}

export const DEEPSEEK_COMPAT = {
  supportsStore: false,
  supportsDeveloperRole: false,
  supportsReasoningEffort: true,
  requiresReasoningContentOnAssistantMessages: true,
  thinkingFormat: 'deepseek',
};

const KIMI_COMPAT = { /* same minus thinkingFormat */ };
const MIMO_COMPAT = { /* same minus thinkingFormat */ };

export function getThinkingCompat(model) {
  const h = getModelHaystack(model);
  if (isDeepSeekStyle(model))  return DEEPSEEK_COMPAT;
  if (h.includes('kimi'))      return KIMI_COMPAT;
  if (isMimo(model))           return MIMO_COMPAT;
  return undefined;
}

function isDeepSeekStyle(m) {
  const h = getModelHaystack(m);
  return h.includes('deepseek') || m.id.includes('qwen3.7') || m.id.includes('qwen3-7');
}
function isMimo(m) {
  const h = getModelHaystack(m);
  return h.includes('mimo') || h.includes('xiaomi');
}
```

### 3.2 Streaming tag parser: `src/core/thinking-tag-parser.js`

Port pi-free's `ThinkingTagParser` verbatim (it's well-engineered):

- Variants: `<thinking>`, `<think>`, `<reasoning>`, `<thought>`.
- Tracks the **trailing possible tag prefix** in the buffer so it never emits `<thin` then `king>` as two text chunks.
- State machine: outside → on open tag enter "thinking" mode → emit `thinking_start`/`thinking_delta` → on close tag emit `thinking_end`.

```js
export class ThinkingTagParser {

  processChunk(textChunk) { /* state machine */ }
  finalize() { /* flush remaining buffer */ }
}
```

### 3.3 Daemon integration

In `src/core/router-daemon.js`, when proxying:

1. Before forwarding the request upstream, look up `getThinkingCompat(targetModel)` and merge into the request body (`reasoning_effort`, etc.) if the client didn't specify.
2. On the streaming response, if `getThinkingCompat` is undefined **but** the upstream emits `<thinking>` tags in `delta.content`, wrap the stream in `ThinkingTagParser` to convert them into structured events.

### 3.4 Tests

- `test/thinking-compat.test.js`: each family detected correctly; haystack matching is case-insensitive; unknown model returns `undefined`.
- `test/thinking-tag-parser.test.js`:
  - Tag split across two chunks (`<thin` + `king>`) → emitted as one thinking block, not partial text.
  - Multiple thinking blocks in one stream.
  - No tags → passes through unchanged.
  - Unicode-decorated tags (`<𝑎𝑛𝑡𝑚𝑙:thinking>`, per pi-free's Cline bridge) — optional stretch goal.

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Shipping compat we don't need (no real streaming yet) | Gate the whole task on 4.1 — don't build speculatively. |
| Wrong compat corrupts a working stream | Default to `undefined`; only apply when family is confidently detected; full test coverage. |
| Provider changes their format | The haystack approach is forgiving; add cases as they appear. |
