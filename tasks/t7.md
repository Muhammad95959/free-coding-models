# createProviderProbe factory + ping-loop abstraction

> **Priority**: P3 — pure refactor; no user-facing change on its own, but it unblocks t1 (probe-cache) and tidies the path to adding new providers. Do **after** t1 lands (or jointly).
> **Inspiration**: `apmantza/pi-free` — `lib/provider-probe.ts` (`createProviderProbe` factory).
> **Cross-surface**: shared core; benefits all surfaces that probe.

---

## 1. Why

Today `src/core/ping.js` + `src/core/ping-loop.js` contain provider-specific branching (NIM vs Groq vs Cerebras auth, endpoint URLs, prompt shapes). Adding a new provider means touching the ping internals. pi-free abstracted this into a **factory**:

```js
const probe = createProviderProbe({
  providerId: 'deepinfra',
  probeModel: async (apiKey, modelId) => { /* return 'ok'|'broken'|'unknown' */ },
  batchSize: 5,
  autoHide: true,
});
const broken = await probe.run(apiKey, models);
```

The factory handles batching, probe-cache integration (t1), auto-hide wiring, and re-registration. Each provider describes **only** how to test one model; everything else is shared.

For us this means:
- `sources.js` gains a per-provider `probe` function (or a reference to one in `src/core/probes/<provider>.js`).
- `ping-loop.js` becomes a thin orchestrator that calls `probe.run(...)` per provider.
- Adding a provider = adding one probe function + one entry in `sources.js`. No more ping-loop edits.

This also makes the **fcm-pi** package (our Pi adapter in `packages/fcm-pi/`) directly reusable — same probe factory, different host.

- [ ] `ping-loop.js` becomes orchestrator-only: load providers → for each, `createProviderProbe(...).run(...)`.
- [ ] Zero behaviour change (this is a refactor — existing tests must stay green).

### Non-goals
- Changing what we probe (same prompt, same endpoint, same latency measurement).
- Adding new providers (that becomes trivial *after* this refactor — call it a follow-up).
- Touching the daemon's health-probe loop (separate code path; can adopt the factory later).

## 3. Technical design

### 3.1 The factory: `src/core/provider-probe.js`

Port pi-free's shape, adapt to our cache (t1):

```js
// src/core/provider-probe.js
import { getModelsDueForProbe, recordProbeResults } from './probe-cache.js';

export function createProviderProbe({
  providerId,           // 'nvidiaNim', 'groq', ...
  probeModel,           // async (apiKey, modelId) => 'ok'|'broken'|'unknown'
  batchSize = 5,
  autoHide = true,
}) {

  async function run(apiKey, models, { useCache = true, onBroken } = {}) {
    // 1. filter to due models (t1 cache)
    const dueIds = useCache
      ? new Set(getModelsDueForProbe(providerId, models.map(m => m.id)))
      : null;
    const candidates = dueIds ? models.filter(m => dueIds.has(m.id)) : models;
    if (candidates.length === 0) return [];

    // 2. batched probe
    const results = [];
    for (let i = 0; i < candidates.length; i += batchSize) {
      const batch = candidates.slice(i, i + batchSize);
      const settled = await Promise.allSettled(
        batch.map(m => probeModel(apiKey, m.id).then(status => ({
          modelId: m.id, status, latencyMs: /* measure */, lastError: null,
        })).catch(err => ({
          modelId: m.id, status: 'broken', latencyMs: null, lastError: err.message,
        })))
      );
      results.push(...settled.map(r => r.value));
    }

    // 3. record + auto-hide (t1)
    recordProbeResults(providerId, results);

    const broken = results.filter(r => r.status === 'broken').map(r => r.modelId);
    if (broken.length && autoHide && onBroken) onBroken(broken);
    return broken;
  }

  return { run };
}
```

### 3.2 Per-provider probe modules: `src/core/probes/<provider>.js`

```js
// src/core/probes/nvidia-nim.js
export async function probeModel(apiKey, modelId) {
  const t0 = Date.now();
  const res = await fetch(`https://integrate.api.nvidia.com/v1/chat/completions`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${apiKey}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ model: modelId, max_tokens: 1, messages: [{ role: 'user', content: 'ping' }] }),
    signal: AbortSignal.timeout(8000),
  });
  if (res.ok) return 'ok';
  if (res.status === 401 || res.status === 403) return 'broken';
  if (res.status >= 500) return 'unknown';   // transient — don't auto-hide
  return 'broken';
}
```

The `latencyMs` measurement moves into the factory (wrap `probeModel` with a timer) so each probe module stays pure.

### 3.3 Registry

```js
// src/core/probes/index.js
import { probeModel as nim } from './nvidia-nim.js';
import { probeModel as groq } from './groq.js';
// ...
export const PROBES = {
  nvidiaNim: { probeModel: nim,     batchSize: 5 },
  groq:      { probeModel,          batchSize: 8 },  // groq is fast, allow more parallelism
  // ...
};
```

### 3.4 Slimmed `ping-loop.js`

```js
import { createProviderProbe } from './provider-probe.js';
import { PROBES } from './probes/index.js';
import { sources } from '../sources.js';

export async function runPingLoop({ onResult, onCached, useCache = true }) {
  for (const [providerKey, src] of Object.entries(sources)) {
    const cfg = PROBES[providerKey];
    if (!cfg) continue;
    const probe = createProviderProbe({ providerId: providerKey, ...cfg });
    await probe.run(src.apiKey, src.models, {
      useCache,
      onBroken: ids => onResult({ providerKey, broken: ids }),
    });
  }
}
```

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Refactor introduces a latency regression (extra indirection) | The factory adds one function call per batch — negligible; verify with a before/after timing test. |
| Per-provider quirks lost in extraction | Extract one provider at a time, keep its tests green, move on. |
| `unknown` (transient) wrongly auto-hides a good model | Factory treats only `broken` as hide-able; `unknown` is recorded but not hidden. |
