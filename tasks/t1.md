# Persistent probe-cache with TTL + auto-hide broken models

> **Priority**: P1 — highest impact on the daily UX (every session re-pings everything today).
> **Inspiration**: `apmantza/pi-free` — `lib/provider-probe.ts` + `lib/probe-cache.ts`.
> **Cross-surface**: MUST work in CLI TUI, Web Dashboard (daemon), and Desktop (Tauri) — all three surfaces share `src/core`.

---

## 1. Why

Today every `pnpm start` / `free-coding-models` invocation re-pings **all ~238 models from scratch**, even models that were healthy 5 minutes ago. This is:

- **Slow** to reach a usable ranking (10–30s on cold start).
- **Wasteful** of free-tier quota on providers that bill per-request even for tiny pings (SambaNova, Groq daily windows, Cerebras before 2026-08-17 shutdown).
- **Not persistent** — a model that has been `broken` for 3 days shows up green again on every fresh launch until its first ping of the day times out.

pi-free solves this with a tiny JSON cache keyed by `provider/modelId`, a **24h TTL** for `ok` results, and **always re-probe** for `broken` results (so a model a user manually un-hid gets re-checked). The ping loop then **skips models whose cache entry is still fresh**, and `broken` models are **auto-hidden** from the default view.

> Note: their `lib/quota-monitor.ts` literally says *"Inspired by free-coding-models' extractQuotaPercent"* — the inspiration flows both ways. This is us reclaiming the lead on the probe-cache axis.

---

## 2. Goals / Non-goals

### Goals
- [ ] Skip pinging any model that returned `ok` within the last **24h** (TTL configurable).
- [ ] Always re-probe models marked `broken` (don't let a stale broken entry suppress cleanup forever).
- [ ] Persist cache across sessions in a single JSON file.
- [ ] Persist cache across surfaces (CLI, daemon, Tauri all read/write the same file).
- [ ] Provide a `--reprobe` / `--no-cache` escape hatch and a TUI key to show hidden broken models.
- [ ] Auto-hide `broken` models from the default ranked list (with a toggle to show them, dimmed).
- [ ] Surface cache freshness in the TUI ("cached 3h ago" hint).
- [ ] Telemetry: count cache hits vs misses per session.

### Non-goals (out of scope, tracked elsewhere)
- Cross-provider failover (t8).
- New ping logic itself (t7 factory).
- Runtime success-rate telemetry (t3) — this task is about **probe** (health check), t3 is about **runtime** (real usage).

## 3. Technical design

### 3.1 File location & atomicity

Cache lives next to the existing daemon state files:

```
~/.free-coding-models/probe-cache.json
```

Also respect `XDG_CACHE_HOME` if set — see how `src/core/cache.js` already resolves paths; reuse that helper, do **not** invent a new path resolver.

Write atomically: write to `probe-cache.json.tmp` then `fs.renameSync` (avoids corruption if the process is killed mid-write — the file is read on every launch). Reuse the same atomic-write helper our daemon log rotation uses, or add a small `writeJSONAtomic(path, data)` to `src/core/shared-helpers.js`.

### 3.2 Schema

```jsonc
{
  "version": 1,
  "providers": {
    "nvidiaNim": {
      "models": {
        "z-ai/glm-5.2": {
          "status": "ok",            // "ok" | "broken"
          "lastProbedAt": "2026-07-25T10:30:00.000Z",
          "latencyMs": 412,          // last successful ping latency (for sort tie-break on cache hit)
          "lastError": null,         // short error string when broken (e.g. "401", "timeout", "html")
          "probeVersion": 2          // bump when ping logic changes → invalidates old entries
        },
        "deepseek-ai/deepseek-v4-pro": {
          "status": "broken",
          "lastProbedAt": "2026-07-25T09:00:00.000Z",
          "latencyMs": null,
          "lastError": "401 Unauthorized",
          "probeVersion": 2
        }
      }
    }
  }
}
```

**`probeVersion`** is critical: when we change ping behaviour (new endpoint, different prompt, t7 factory lands), bumping this number invalidates the entire cache in one go — no manual purge needed.

### 3.3 Module: `src/core/probe-cache.js`

New pure-logic module (so it's unit-testable, per AGENTS.md "Pure logic functions are in `src/utils.js`"). API:

```js
// src/core/probe-cache.js
export const DEFAULT_PROBE_TTL_MS = 24 * 60 * 60 * 1000;  // 24h
export const CURRENT_PROBE_VERSION = 2;

export function getModelsDueForProbe(providerKey, modelIds, {
  ttlMs = DEFAULT_PROBE_TTL_MS,
  now = Date.now(),
  cache,                    // injected for tests
  probeVersion = CURRENT_PROBE_VERSION,
} = {}) { /* returns string[] of model IDs that need probing */ }

export function isCacheFresh(providerKey, modelId, opts) { /* boolean */ }

export function recordProbeResults(providerKey, results, opts) {
  // results: [{ modelId, status: 'ok'|'broken', latencyMs, lastError }]
  // mutates in-memory cache + schedules async flush
}

export function loadCache(opts) { /* reads JSON, migrates old versions */ }
export function flushCache(opts) { /* atomic write */ }
export function clearCache(opts) { /* nuke file (for --reprobe) */ }
export function getCacheStats(opts) { /* { total, ok, broken, freshCount, staleCount } */ }
```

**Freshness rules** (mirror pi-free exactly):
1. No entry → due for probe.
2. `probeVersion !== CURRENT_PROBE_VERSION` → due for probe (silently re-probed, entry overwritten).
3. `status === 'broken'` → **always due** (allows recovery detection).
4. `now - lastProbedAt >= ttlMs` → due for probe.
5. Otherwise → fresh, skip.

### 3.4 Integration into `src/core/ping-loop.js`

Today `ping-loop.js` iterates `MODELS` and fires pings. Change to:

```js
const dueIds = new Set(getModelsDueForProbe(providerKey, modelIdsForProvider));
const toPing = models.filter(m => dueIds.has(m[0]));
const cachedHealthy = models.filter(m => !dueIds.has(m[0]) && cacheEntry?.status === 'ok');

// 1. Inject cached results immediately so the TUI shows something in <100ms
emit('cached', cachedHealthy.map(/* build result from cache */));

// 2. Ping only the due ones (parallel, same concurrency as today)
const freshResults = await pingBatch(toPing);
recordProbeResults(providerKey, freshResults);

// 3. Merge: cached + fresh → final ranked list
```

**Critical**: cached results MUST be injected into the TUI immediately — otherwise the user sees an empty table for the duration of the live ping. This is the single biggest perceived-speed win.

### 3.5 Auto-hide behaviour

In `src/core/model-merger.js` (or wherever the final ranked list is built), add a `hidden` flag:

```js
result.hidden = (cacheEntry?.status === 'broken');
```

The TUI then:
- **Default view**: hides `hidden === true` rows (or shows them greyed-out at the bottom — A/B with Vanessa).
- **Toggle** (new `B` key, currently free per `tui-state.js`): reveals them.
- Footer hint: `⚡ 12 cached · 🔴 3 broken hidden (press B to show)`.

When a `broken` model is re-probed and comes back `ok`, `recordProbeResults` flips `hidden` to `false` automatically — no user action needed.

### 3.6 Surface parity

| Surface | What it does |
|---|---|
| **CLI TUI** (`bin/free-coding-models.js`) | Reads cache on boot, injects cached, pings due, hides broken. New `--reprobe` flag. |
| **Daemon / Web** (`src/core/router-daemon.js`) | Reuses the same `probe-cache.js`. Daemon's existing health-probe loop (per the PRD, "Health probes ✅ Backend done") gets the cache layer bolted on. The `/health` endpoint exposes `cachedCount` / `brokenCount`. |
| **Desktop (Tauri)** | Calls the same daemon endpoints. No separate logic. |

The file is shared because all surfaces resolve to the same `~/.free-coding-models/probe-cache.json`.

**Concurrency**: if the daemon and a CLI are running at once, both may try to flush. Use atomic-write + read-merge-write (load → merge only this process's deltas → write). pi-free sidesteps this because only Pi writes; we have to be explicit.

### 3.7 CLI flags & TUI keys

- `--reprobe` (alias `--no-cache`): force-rebuild the cache this run.
- `--probe-ttl <ms>`: override the 24h default (power users / debugging).
- `--show-broken`: don't auto-hide (one-shot override).
- TUI: `B` key to toggle "show broken".

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Stale `ok` entry hides a model that broke seconds ago | TTL is a tradeoff; default 24h, surface "cached Xh ago" in TUI; manual `--reprobe` or a future "re-probe visible rows" key. |
| Cache file grows unbounded as catalog evolves | On `loadCache`, prune entries whose `modelId` is no longer in `sources.js` (cross-ref `MODELS`). One-time prune per boot. |
| Two surfaces race on write | Read-merge-write + atomic rename; worst case one batch of deltas is lost, not the whole file. |
| User on a fresh machine sees empty cache | Same as cold start today — no regression. |
| `probeVersion` bump nukes everyone's cache | Acceptable and intended; document in changelog. |
