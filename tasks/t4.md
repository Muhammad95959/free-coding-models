# Prefix-indexed benchmark catalog with lazy load + extended metrics

> **Priority**: P2 — performance + metric-richness; low risk, contained change.
> **Inspiration**: `apmantza/pi-free` — `provider-failover/benchmark-lookup.ts` + `hardcoded-benchmarks.ts`.
> **Cross-surface**: pure logic in `src/core/benchmark.js`, consumed everywhere.

---

## 1. Why

Today `src/core/benchmark.js` looks up a model's benchmark by linear scan, and `sources.js` carries a **single** `swe_score` per model. Two problems:

1. **Lookup is O(n)** across the whole catalog on every render/sort. With ~238 models × frequent re-renders in the TUI, this adds up.
2. **We only show SWE-bench**. pi-free pulls from **Artificial Analysis** and stores per model: Coding Index, Math Index, Agentic Index, Reasoning Index, MMLU-Pro, GPQA, HLE, context window, supports-reasoning, supports-vision. That's a much richer comparison surface.

pi-free solves lookup cost with a **prefix index**: every model key is split on `-`, and each prefix (`deepseek`, `deepseek-ai`, `deepseek-ai/deepseek`, …) maps to its candidate entries. A lookup only visits variants of that base model, not the whole catalog. They also lazy-load the JSON via a `Proxy` so the catalog isn't parsed at startup.

---

## 2. Goals / Non-goals

### Goals
- [ ] Lookup a model's benchmark in **O(key length)** instead of O(catalog size).
- [ ] Parse the benchmark catalog **lazily** (only when first lookup happens), not at module load.
- [ ] Extend the per-model benchmark record with: Coding Index, Math Index, Agentic Index, Reasoning Index, MMLU-Pro, GPQA, HLE, supports-reasoning, supports-vision.
- [ ] Surface the new metrics in the TUI (new columns / detail view) and Web Dashboard.
- [ ] Keep `sources.js` as the source of truth for SWE-bench (already curated); overlay the extended metrics from a generated JSON.

### Non-goals
- Replacing `sources.js` (it's curated and tested). The extended catalog is **additive metadata**, fetched/generated separately.
- Live-fetching Artificial Analysis on every run (we ship a generated JSON, refreshed by a script — mirror pi-free's `scripts/update-benchmarks.ts`).
- Changing the tier system (S+/S/A+… stays, derived from SWE-bench).

### 3.2 Lazy load via `Proxy`

Mirror pi-free's `hardcoded-benchmarks.ts` — defer JSON parsing until first access:

```js
// src/core/benchmark.js
import { readFileSync } from 'node:fs';

let _cache = null;
function load() {
  if (_cache) return _cache;
  try {
    _cache = JSON.parse(readFileSync(new URL('../data/benchmarks.json', import.meta.url), 'utf8'));
  } catch (err) {
    console.warn('[benchmark] failed to load catalog, scoring disabled:', err.message);
    _cache = {};
  }
  return _cache;
}

// Lazy proxy: parse on first property access, not on import
export const BENCHMARKS = new Proxy({}, {
  get(_t, prop, receiver)       { return Reflect.get(load(), prop, receiver); },
  has(_t, prop)                 { return Reflect.has(load(), prop); },
  ownKeys()                     { return Reflect.ownKeys(load()); },
  getOwnPropertyDescriptor(_t, p){ return Reflect.getOwnPropertyDescriptor(load(), p); },
});
```

**Why it matters**: today every CLI launch parses the whole benchmark catalog even if the user only runs `--help`. Lazy parse shaves ms off cold start.

### 3.3 Prefix index

```js
let _index = null;
function getIndex() {
  if (_index) return _index;
  const exact = new Map();
  const variants = new Map();
  for (const [key, data] of Object.entries(load())) {
    exact.set(key, data);
    const segments = key.split('-');
    for (let end = 1; end < segments.length; end++) {
      const prefix = segments.slice(0, end).join('-');
      const arr = variants.get(prefix) ?? [];
      arr.push([key, data]);
      variants.set(prefix, arr);
    }
  }
  _index = { exact, variants };
  return _index;
}

export function lookupBenchmark(modelId) {
  const { exact, variants } = getIndex();
  if (exact.has(modelId)) return exact.get(modelId);
  // fall back to prefix walk: longest prefix first
  const segments = modelId.split('-');
  for (let end = segments.length - 1; end >= 1; end--) {
    const candidates = variants.get(segments.slice(0, end).join('-'));
    if (candidates?.length) return pickBestMatch(candidates, modelId);
  }
  return null;
}
```

### 3.4 Merge with `sources.js`

`sources.js` keeps `swe_score` (curated, the tier signal). The extended catalog is overlaid:

```js
// in model-merger.js or schema-normalizer.js
const ext = lookupBenchmark(model.id);
model.bench = {
  swe: model.sweScore,                    // from sources.js (existing)
  coding: ext?.codingIndex   ?? null,
  math:   ext?.mathIndex     ?? null,
  agentic:ext?.agenticIndex  ?? null,
  // ...
};
```

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Artificial Analysis ToS / scraping | Check their `update-benchmarks.yml` for the canonical fetch method; prefer an official endpoint. If blocked, ship a one-time generated JSON and document how to refresh. |
| Benchmark names diverge from our model IDs | The prefix fall-back + `originalModel` debugging field (pi-free's trick) surfaces collisions. |
| Stale data misleads users | Always show `lastUpdated`; TUI highlights entries older than 30 days. |
| Catalog bloats bundle | `benchmarks.json` is ~10k lines at pi-free scale; gzip in npm tarball; acceptable. |
