# Passive quota monitoring via response headers

> **Priority**: P1 — eliminates wasted quota-fetch requests and keeps quota *live* during real usage.
> **Inspiration**: `apmantza/pi-free` — `lib/quota-monitor.ts` (which itself credits us: *"Inspired by free-coding-models' extractQuotaPercent"*).
> **Cross-surface**: shared `src/core/provider-quota-fetchers.js` is consumed by CLI, daemon, and Tauri.

---

## 1. Why

Today we discover a provider's remaining quota by **actively fetching** a dedicated quota endpoint (see `src/core/provider-quota-fetchers.js` + `test/provider-quota-fetchers.test.js`). Problems:

- **Extra requests** that consume the very quota we're trying to measure (SambaNova per-minute windows, Groq daily caps).
- **Not all providers expose a quota endpoint** — for those we currently show nothing.
- **Stale between polls** — the daemon polls every N seconds; between polls the displayed `%` is wrong, so users get rate-limited mid-request.

pi-free's insight: **every chat-completion response already carries rate-limit headers**. By hooking the response pipeline (they use Pi's `after_provider_response` event) and parsing 5 header variants in priority order, they get a *free, always-fresh* quota signal with **zero extra requests**.

We should do the same on **two** of our surfaces:

1. **Daemon reverse-proxy** (`src/core/router-daemon.js`) — every routed request's response passes through us; we parse the headers there.
2. **Ping responses** (`src/core/ping.js`) — even health-check pings return headers; we can pre-warm quota before the user ever routes.

The active `provider-quota-fetchers.js` stays as a **fallback** for providers that don't emit headers (e.g. some that need an explicit `/usage` call).

---

## 2. Goals / Non-goals

### Goals
- [ ] Parse rate-limit headers from **every** response that flows through the daemon and through pings.
- [ ] Support the 5 header-pair variants pi-free supports (see 3.2) **plus** any we already handle.
- [ ] Merge with existing active-fetch quota so the displayed value is the freshest of the two.
- [ ] Mark quota as **stale after 5 min** (no header seen recently → fall back to active fetch or hide the chip).
- [ ] Expose via `/stats` and the TUI footer so the user sees live `%` per provider.
- [ ] Zero extra network requests compared to today.

### Non-goals
- Replacing `provider-quota-fetchers.js` entirely (keep as fallback).
- Per-model quota (we track per-provider, since headers are per-provider-key).
- Quota-based auto-routing decisions (separate task; this is observability only).

## 3. Technical design

### 3.1 Module: extend `src/core/provider-quota-fetchers.js`

Add a passive tracker alongside the existing active fetchers:

```js
// in-memory quota state (mirrors pi-free's _quotaState Map)
const _passiveQuota = new Map(); // providerKey -> QuotaSnapshot

export function processResponseHeaders(providerKey, headers) {
  const extracted = extractQuota(headers);
  if (!extracted) return;
  _passiveQuota.set(providerKey, { ...extracted, percent, lastUpdated: Date.now() });
}

export function getQuota(providerKey) { /* merge passive + active, return freshest */ }
export function getAllQuotas() { /* ReadonlyMap for /stats */ }
export function formatQuotaStatus(providerKey) { /* "⚠️ groq: 12/100 (12%)" */ }
```

### 3.2 Header-pair variants (priority order)

Straight from pi-free's `HEADER_PAIRS`, each pair is `[remaining, limit]`:

```js
const HEADER_PAIRS = [
  // Per-minute (most common)
  ['x-ratelimit-remaining-requests', 'x-ratelimit-limit-requests'], // SambaNova
  ['x-ratelimit-remaining',          'x-ratelimit-limit'],          // Mistral
  ['ratelimit-remaining-requests',   'ratelimit-limit-requests'],
  ['ratelimit-remaining',            'ratelimit-limit'],
  // Per-day
  ['x-ratelimit-remaining-requests-day', 'x-ratelimit-limit-requests-day'], // SambaNova daily
  ['x-ratelimit-remaining-day',          'x-ratelimit-limit-day'],
];
```

**Case-insensitive**: normalize all header keys to lowercase before matching (some proxies vary casing). Return the **first** pair where both `remaining` and `limit` parse as finite numbers and `limit > 0`.

### 3.3 Integration points

#### 3.3.1 Daemon reverse proxy (`src/core/router-daemon.js`)

The daemon already proxies `/v1/chat/completions`. In the response handler (after we forward headers, before we stream the body to the client), call:

```js
processResponseHeaders(upstreamProviderKey, upstreamResponse.headers);
```

This is the **highest-value** hook — every real user request updates the quota for free.

#### 3.3.2 Ping responses (`src/core/ping.js`)

Our pings already issue a tiny chat completion; the response headers are currently discarded. Capture them:

```js
const res = await fetch(...);
processResponseHeaders(providerKey, res.headers);
```

This **pre-warms** the quota display before the user ever routes through the daemon — useful for the CLI-only flow where the daemon isn't running.

#### 3.3.3 Active fetcher merge

`getQuota(providerKey)` returns the **freshest** signal:

```js
function getQuota(providerKey) {
  const passive = _passiveQuota.get(providerKey);
  const active  = lastActiveFetch.get(providerKey); // existing
  const candidates = [passive, active].filter(Boolean);
  if (candidates.length === 0) return null;
  return candidates.reduce((a, b) => a.lastUpdated > b.lastUpdated ? a : b);
}
```

### 3.4 Staleness & display

- A passive snapshot is **stale after 5 min** with no new header (mirror pi-free).
- TUI footer gains a per-provider chip when the daemon is running: `📊 groq 78% · sambanova 41%`.
- Web Dashboard `/stats` returns `quota: { groq: {remaining, limit, percent, lastUpdated, source}, ... }`.

### 3.5 Source attribution (debugging)

Each snapshot stores `source` (which header variant matched). Surface in `--debug` mode so we can see *why* a provider shows 100% (maybe a proxy strips headers → source = `null` → fall back to active fetch).

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Provider strips headers behind a proxy | `source` field reveals it; fall back to active fetch silently. |
| Headers report per-minute but user thinks it's daily | Store which variant matched; show "min" vs "day" in the tooltip if the pair ends in `-day`. |
| Memory growth from old entries | Cap `_passiveQuota` to known providers; evict on provider removal. |
| Race: two routed requests update same provider concurrently | Map writes are atomic in JS (single-threaded event loop); no lock needed. |
